# NIVAR G2 research — 11 September 2026

This is research and experimental art direction, not human approval. G0/G1 remains the authority. Sources below were fetched during this run; screenshots are in `references/`. Public site claims are treated as that company's positioning, not independently verified facts.

## Direction that the research supports

Build a house whose characteristic gesture is opening the evidence. A restrained editorial surface can invite a reader in, but the distinctive behavior must occur when a number or conclusion is selected: the source, period, unit, transformation, uncertainty, and challenge become visible beside it. The brand is not merely a serif over gray paper. It is a recurring relationship between a question and an inspectable record.

Keep the mineral territory almost achromatic. Give typography three jobs, keep the NIVAR wordmark constant, and change density according to the task. Let the five families differ in their organizing object: an issue of a publication, an argument, a learning path, a working application, and a measured physical object. These are original design deductions from the brief and research, not claims about the references.

## What materially changed the direction

### Current motion bar: Subframe through 60fps

[The captured Subframe mobile sequence](https://60fps.design/appsites/subframe-hero-illustration-scroll-animation) follows one material object through token, display, visual UI, and code. A stable stage makes the transformations readable. Functional copy travels with the matching state. This is the best transferable mechanism: evidence must remain recognizably the same evidence as NIVAR measures, organizes, observes, questions, and transmits it.

The literal object, phone framing, and retro computer are unsuitable for NIVAR. The useful material is an evidence sheet, calibrated instrument plane, or document fragment. The film should have a strong complete first frame, an obvious causal change at each verb, and a clear return to inquiry. `bar.md` defines the seven observable criteria. Reference PNGs capture requested player positions 10%, 45%, and 80%; they are not exact timestamp measurements. The final PNG was reopened locally and verified to show the code state.

### Current composition bar: Linear

The [live Linear homepage](https://linear.app/) was inspected in the browser. It currently presents a flat interactive issue vignette: issue title, narrative context, activity, and properties. Its main transferable mechanism is showing a real product situation at enough scale to read. Its headline, supporting sentence, and application sit at distinct scales. The screenshot is `linear-home-2026-09-11.png`.

For NIVAR, reserve the product passage for one legible relationship: a source record, a chart signal, and the interpretation it supports. Avoid reducing many application screens to visual texture. Linear's visual skin and developer-tool positioning should not be copied.

### Provenance: Our World in Data

[OWID's Grapher redesign](https://ourworldindata.org/redesigning-our-interactive-data-visualizations) places sources prominently and opens deeper metadata in context. It separates dataset views from view-specific controls, supports chart/table/map views, and exposes the current chart configuration in shared previews. NIVAR can use the same interaction logic: a compact source line is always present; a provenance panel expands beside the selected result; chart configuration and source context travel together.

Important implementation caution: the article's historical text calls Grapher MIT, but its current footer links to a custom software license requiring permission for reuse. No OWID code was copied. Mechanisms are referenced, not licensed software assumptions.

### Operational discipline: NASA Display Standard

[NASA's Display Standard](https://www.nasa.gov/reference/appendix-f-vol-2/) explicitly addresses consistent locations, task-flow alignment, stale telemetry indication, fixed-width numeric data, labels adjacent to values, and errors that explain corrective action. These are useful human-factors mechanisms for Terminal and Operator, not a requirement to mimic spacecraft UI.

NIVAR translation: keep region and period in persistent locations; never move major modules when a value changes; reserve a stable status location; distinguish unavailable, stale, observed, and historical. A missing value should leave geometry intact and explain the state. Do not import NASA's ASCII-only or aerospace-specific alarm conventions into Portuguese software.

## Wordmark and family architecture

[Logobook's N archive](https://logobook.com/letter/n/) and [engineering archive](https://logobook.com/business/engineering/) were visually inspected and saved. The collection demonstrates how a few large counterspaces and a single structural intervention can carry recognition in monochrome. It also shows that a striped, woven, or waveform N is already crowded territory.

Recommended NIVAR experiment: a custom wordmark with a shared diagonal angle through N, V, and A; ordinary I as a visual rest; an open A only if the word still reads immediately at navigation size; an R whose leg provides a measured return rather than a flourish. Start with strong solid silhouettes. Test the N separately at 16px. Do not embed six mythological symbols in five letters. This is an original proposed construction, not a traced reference.

[NASA's brand architecture](https://www.nasa.gov/nasa-brand-center/brand-guidelines/) keeps agency identity primary and gives separate rules to emblems and identifiers. The useful principle is hierarchy: NIVAR stays constant, family name provides context, and each emblem has a specific behavioral role. NASA marks are protected and were not used. For NIVAR, keep small UI symbols distinct from detailed ceremonial emblems; micro marks must not become illegible miniature illustrations.

## Typography decision

The G1 trio still has a strong factual basis. Retention can be a considered decision rather than legacy inertia:

- [Newsreader, Production Type](https://productiontype.com/font/newsreader) was designed for extended screen reading and provides optical sizes. [Its primary repository](https://github.com/productiontype/Newsreader) documents Latin Plus coverage and SIL OFL. Use it for a whole interpretive thought, not one decorative italic word in an otherwise sans headline.
- [Instrument Sans's primary repository](https://github.com/Instrument/instrument-sans) documents variable width/weight, tabular figures, stylistic alternates, broad language support, and OFL. It can remain the organizing UI voice. Enable tabular figures in numeric columns; do not squeeze body text with the width axis merely to fit a bad layout.
- [IBM's Plex documentation](https://www.ibm.com/design/language/typography/typeface/) documents extended Latin coverage, currency symbols, and an open font license. Mono should be a compact record voice: timestamps, IDs, units, source labels. Whole explanatory paragraphs should use the reading voice.

Acceptance strings: `São Paulo · geração · análise · R$ 1.234,56/MWh · 12,4% · 03:27 BRT · O0 Il1`. Inspect them at 11px, 14px, and 18px on both substrates. Font rights remain attached to the exact files distributed.

## Data and interaction rules for the build

[Carbon's chart guidance](https://carbondesignsystem.com/data-visualization/color-palettes/) distinguishes categorical, sequential, and alert palettes. NIVAR should likewise separate brand accents from data encoding. Direct labels, line patterns, and explicit signs make comparisons work without color alone. Its [accessibility guidance](https://carbondesignsystem.com/guidelines/accessibility/color/) also highlights testing text against every point of an animated background; place hero copy on a stable contrast field.

Original application recommendations:

1. Terminal: persistent context strip; dominant situation/market chart region; quieter interpretation rail; source drawer keyed to selection. Region/period selection updates relevant modules without changing their positions.
2. Operator: an attention queue organized by real state, age, blockers, and ownership. A selected case opens a stable adjacent detail region. Do not manufacture SLA or priority data that the domain model does not contain.
3. Case: evidence and reasoning remain visible together. A selected field reveals its source document location when that location exists. Otherwise state the traceability limit honestly. Separate extraction from interpretation and opinion.
4. Account: a deliberately composed entry with one clear account scope and trust context. Preserve existing auth semantics, redirects, errors, and recovery controls. Never fabricate provider sign-in buttons.
5. Mobile Terminal: preserve useful reading and selecting tasks, then disclose which dense comparisons require more width. Avoid hiding source metadata solely to make a card fit.

## ThreeUI and asset implications

The current [ThreeUI Community README](https://github.com/MengTo/threeui/blob/main/README.md) was fetched with the connected GitHub tool. It describes MIT-licensed Community application/component code and ThreeUI-authored imagery, separate OFL font files, and per-component npm subpath imports. Pro implementation is deliberately absent from the public package. Remote thumbnails/previews are not redistributed with Community.

Borrow only a meaningful mechanism, such as a persistent plane or connected transformation. Do not load an entire effects catalogue. If using code, retain its license and verify the specific asset notices. A concept render or generated documentary-style scene remains illustrative, never a measured object or source of market truth.
